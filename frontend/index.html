Theoretical Time & Space Complexity Analysis

Custom Indexed Min-Heap
  • Insert: O(log N) — Bubbles up at most tree height h = ⌊log₂ N⌋.
  • Extract-Min: O(log N) — Replaces root and bubbles down in O(log N).
  • Priority Update: O(log N) — Position HashMap provides O(1) lookup, then bubbles in O(log N).
  • Space Complexity: O(N) — Compact array plus position dictionary.
  • Conclusion: Optimal for high-throughput hospital emergencies where arrivals and status changes occur continuously.
Naive Sorted List
  • Insert: O(N log N) or O(N) — Re-sorting the array on each incoming patient is extremely slow for large queues.
  • Extract-Min: O(1) — Minimum element is always at index 0.
  • Priority Update: O(N log N) — Requires searching and full re-sorting.
  • Space Complexity: O(N).
  • Conclusion: Severe quadratic slowdown O(N² log N) when processing batches of emergency intake.
Naive Linear Scan (Unsorted List)
  • Insert: O(1) — Appends to the end of the array.
  • Extract-Min: O(N) — Must iterate through every waiting patient to find the most critical.
  • Priority Update: O(1) — Directly modifies element if index is known.
  • Space Complexity: O(N).
  • Conclusion: Fast registration, but unacceptable doctor allocation lag. Extracting 10,000 patients takes over 11 seconds!
